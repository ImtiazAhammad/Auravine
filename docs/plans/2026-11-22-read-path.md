# Read Path (Phase 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native, inline) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The public site reads its content (projects, blog posts, FAQs, tech items, site settings) from Supabase, in the visitor's language, and falls back to the static data when Supabase is unreachable. A flag keeps the old behaviour until cutover.

**Architecture:** A server-only content layer (`src/lib/content/`) fetches published rows from Supabase PostgREST with the anon key, caches them in the Next.js Data Cache (`fetch` with `revalidate` and the tag `content`), localizes them (Bangla with English fallback) and maps them back to the existing `PortfolioData` shape. The root layout calls it once and hands the result to a `ContentProvider`. Client components replace `import { portfolioData }` with `useContent()`, so no component's field access changes. `/api/revalidate` lets the backend refresh the cache after an admin save (used from Phase 5).

**Tech Stack:** Next.js 16 (no `cacheComponents`), React 19, next-intl, TypeScript, vitest (new), Supabase PostgREST over plain `fetch`.

**Spec:** `docs/BACKEND-PLAN.md` (Architecture rules 1 to 3, Phase 3), `docs/plans/phase2-findings.md` (what is seeded and how). Next.js caching behaviour: `node_modules/next/dist/docs/01-app/02-guides/caching-without-cache-components.md`.

## Global Constraints

- **AGENTS.md:** this is Next.js 16 with breaking changes; read the matching doc under `node_modules/next/dist/docs/` before using a Next API. `revalidateTag` takes two arguments: `revalidateTag('content', 'max')`.
- **Public reads never depend on Python** (BACKEND-PLAN rule 1). The content layer talks only to Supabase.
- **Anon key only.** The service-role key never enters the Next.js app. Server-only env names: `SUPABASE_URL`, `SUPABASE_ANON_KEY` (not `NEXT_PUBLIC_*`).
- **Flag:** `CONTENT_SOURCE` is `supabase` or `static`; unset means `static`.
- **Bilingual jsonb** is `{"en": "...", "bn": "..."}`; `en` always exists, `bn` is optional and falls back to `en`. Project `details` is `{"en": {...}, "bn": {...}}` and is localized the same way.
- **Draft is invisible.** A slug absent from a successful Supabase response is a 404. Static fallback happens only on a failed fetch, never on a missing row.
- **Not in the database, stay static:** `experiences`, `education`, `achievements`, `gallery` (their pages are unpublished). `getContent` takes them from `portfolio.ts`.
- **Only the content layer imports `@/data/portfolio`** (plus tests and the seed export script). Client components never do.
- **No new runtime dependencies.** `vitest` is a devDependency.
- UI strings in `messages/*.json` are untouched.

## Review Focus

1. **Supabase down, slow or misconfigured:** every page still renders from static data within the timeout; no unhandled rejection reaches the visitor. (Task 4)
2. **Unpublished or unknown slug while Supabase is healthy:** `/projects/<draft>` and `/blog/<draft>` return 404, not the static copy. (Task 4, Task 6)
3. **Row with only the required fields** (admin-made project: no hero image, no details, no links; blog post with no cover): maps to a safe `Project` / `BlogPost` with placeholders and empty lists, no crash in the components that render them. (Task 2)
4. **Bangla missing on some fields:** a Bangla visitor sees English for those fields, never an empty string or `undefined`. (Task 1)
5. **Secrets:** `/api/revalidate` fails closed (500 when its secret is unset, 401 on a wrong or missing one); no service-role key and no `NEXT_PUBLIC_` Supabase variable exists. (Task 5, Task 7)
